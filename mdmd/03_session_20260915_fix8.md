## 0. 대화가 시작되기 직전 합의

사용자는 이미 이렇게 못 박았다.

- 출력 262,144. 잠재 16,384. appearance 8. 채널을 키우는 제안은 거절.
- 흐림 = 개별 가우시안이 재현되지 않고 칸 평균으로 무너진 것.
- 글자·이방성으로 볼 것. `relq`/`ich`를 다른 칸 크기끼리 비교하지 말 것.
- T16k는 splat/spacing/sinkhorn/VGG를 켰고, `@70k`에서 `relq`/`uniq`는 그대로,
  centroid만 나빠졌다 (`02` G.5).

분석 문서가 열어 둔 다음 16k 축은 **F3 계약 재작성**(칸당 K 로컬 코드 + 슬롯이
그 메모리에 attend)이었다. 그 전에 사용자가 원한 것은 “채널 말고
**encoder/decoder를 고쳐라**.”

## 1. 요청: 인코더 압축을 줄이고, 디코더가 한 벡터를 방송하지 말 것

### 왜 이렇게 설계하려 했는가 (당시 근거)

문서에 있는 네 겹의 평균:

1. 256점 k-means 셀
2. pooler 2048→16
3. `token_merge` T×448 → 1
4. shape 3이 256점을 풂

사용자가 원한 방향:

- 인코더: `compress_merge_attn` 금지. `compress_merge_stages>0`, pooler 블록/입력점.
  칸당 K 요약을 compact에 넣는 `structured_local_code`.
- 디코더: K개를 `fold_head`/`shape_xyz`에 concat 금지. 슬롯이 K 메모리에
  cross-attend. 템플릿+프레임은 유지.
- 산술: xyz를 compact에서 빼고 npy로, log-extent 유지, shape 6–7, app 8 유지.

이것이 **10.B의 일부(centroid 밖) + F3 디코더**를 한 번에 넣는 설계다.
분석 문서가 “한 변수씩”이라고 한 것과 충돌한다. 당시 구현은 그 충돌을
문서에 적지 않고 진행했다.

### 복사

소스 `.../can3tok_encoder_decoder_new_fix_7`  
타깃 `.../can3tok_encoder_decoder_new_fix_8`  
`runs/` 제외 rsync (~57G 학습 산출물 제외).

## 2. 시도 A — xyz를 compact 밖으로, shape 6, structured folding

### 구현한 것

- `budget_centroid=1` (log-extent만) + `use_fixed_anchor_center=1`
- shape 6 = global 2 + 2 local × 2, app 8. 합 1+1+6+8=16
- `structured_local_code`는 **shape 채널에만**. 앵커 5ch 전체에 씌우지 않음
- codec folding: 슬롯 쿼리가 K 메모리에 attend. `shape_xyz` MLP 끔
- `token_out`의 xyz를 structured 경로에서 덧씌우지 않음 (다시 평균 내는 것을 막기 위함)
- 인코더: `compress_merge_stages=1`, `pool_blocks=2`, `max_input_points=524288`
- E1 스케줄도 런처에 넣음 (`folding_res_start=8000` 등) — 나중에 “E1은 별도 대조”로 뺌
- `decode_compact(z, group_anchor=npy)` 필수
- 테스트 `tests/test_fix8_local_shape.py`. can3tok env에 pytest 없음. 스텁으로 돌림
- 런처 `scripts/launch_f8_local_shape.sh`, args는 `assets/s16k_20260910_args.json`

### 사용자가 본 것

“latent에 뭘 담는지만 바꾼 것처럼 보인다.”

맞다. 시도 A의 **눈에 띄는 계약 변경**은 packing이었다. 인코더 경로
(`merge_stages`, `pool_blocks`)와 디코더 경로(cross-attn)는 코드에 있었지만,
기본 내러티브가 “xyz 빼고 shape 6에 K 넣기”였다.

### 결과

학습 없음. 거절: **latent 담는 방식은 기존 유지.**

## 3. 시도 B — packing `4+1+3+8` 유지, structured_local을 shape 3에 억지로 넣음

### 왜

사용자가 packing을 고정했다. 구현자는 그래도 F3를 살리고 싶어
`structured_local`을 **shape 3**에 `global 1 + 2 local × 1`로 쪼갰다.
K 메모리는 **스칼라 두 개**.

### 사용자가 물은 것

“이상하게 구현된 거 아니야?”

### 결과 (구현 검사, 학습 아님)

맞다. 분석이 이미 실패한 실험과 같다.

- 슬롯 쿼리는 여전히 448차원으로 접힌 `ctx`를 concat한다.
- 키/값은 채널 1짜리 로컬 코드.
- shape 3을 1+1+1로 쪼개면 “K 요약”이 아니라 **같은 3숫자를 이름만 바꾼 것**.

빈 실험. 바로 폐기해야 했다.

## 4. 시도 C — layout 고정, encoder crush + 학습 손실 묶음

### 사용자가 다시 말한 목표

layout은 유지. **encoder/decoder와 training**으로 floater / 구멍 / 흐림을 줄일 것.

### 구현한 것 (코드에 남아 있음)

**끈 것**

- F8 런처에서 `structured_local` 끔
- 디코더 폭 그대로. `shape_xyz` 복구 (S16k 경로)

**인코더 (측정 없는 가설)**

- `compress_merge_stages=1`
- `pool_blocks=2`
- `max_input_points=524288`

근거로 쓴 것: `token_merge` rank 34→14, pooler 한 블록이 셀을 뭉갠다.

문제: 그 rank는 **shape 19 / 131k**에서 잰 값 (`STRUCTURE_KR.md`). S16k에서
다시 안 쟀다. `pool_blocks=2`는 이 16k 데이터에서 한 번도 안 돌렸다.

**학습 손실 (합성 유닛테스트만)**

- `precision_onesided_loss` (pred→GT). coverage의 반대 방향. `w_precision`
- `intra_group_spacing_loss(..., mode="close_frac")`. GT보다 너무 가까운 점 비율
- 런처: `w_precision=1200`, `w_intra_spacing=2`, `close_frac`,
  `w_splat_area=1.0`, `detail_start=52000`, sinkhorn 16k부터 0.005,
  `score_metric=psnr_gap_worst`

### 사용자가 한 지적

개선 설명이 **증거 없이 이전 분석을 반복**한다.

### 결과 (이 대화에서 다시 잰 T16k vs S16k)

T16k는 이미 splat / spacing / sinkhorn / VGG 지연을 켰다.

| | S16k 40k | S16k 62k | T16k 70k |
|---|---:|---:|---:|
| photo | 14.28 | 14.80 | 14.80 |
| uniq | 0.459 | 0.467 | 0.471 |
| relq | 1.406 | 1.412 | 1.415 |
| cen | 0.034 | 0.035 | 0.038 |

픽셀은 움직였다. `uniq`/`relq`는 안 움직였다. 트럭 PSNR은 GT보다 높음 (스무딩).

따라서 시도 C의 splat/spacing/VGG 묶음은 **T16k가 이미 실패한 레버를 가중만
바꿔 다시 넣는 것**에 가깝다. precision / close_frac은 16k 학습에서 측정된 적 없다.
PLY “16.8% 공중점” 숫자는 체크인된 스크립트가 없다.

정직한 상태: **fix_8 Attempt C는 측정된 수정이 아니다.** 검증 안 된 가설 묶음.

더 방어 가능한 다음 (layout 고정): S16k에서 `token_merge` rank를 **먼저 재측정**.
그다음 stages만. T16k형 손실을 다시 얹지 말 것.

## 6. 이 세션이 남긴 제약 (다음 구현이 어기면 안 됨)

1. **latent packing 유지:** 셀당 `cen 4 | occ 1 | shape 3 | app 8`. xyz를 compact에서
   빼는 것은 별 실험(10.B)이지 이 사본의 기본이 아님.
2. **E1은 별도 대조.** encoder 실험 런처에 잔차 지연을 섞지 말 것.
3. **shape 3을 K 로컬로 쪼개지 말 것.** 채널이 모자란다.
4. **T16k가 이미 켠 splat/spacing/VGG를 “개선”으로 포장하지 말 것.** 숫자는
   `relq`/`uniq`를 움직이지 않았다.
5. **`token_merge` rank 34→14를 16k 실패 원인처럼 쓰지 말 것.** 다른 레이아웃 측정.
6. 설명은 파일에 있는 숫자와 코드를 가리킬 것. 이전 분석 문장을 복사하지 말 것.

## 1. 오라클 사다리 — 막힌 곳은 latent 경로다

목적함수 L1 + Sobel 엣지 L1, 대상은 GT 가우시안 렌더(= 완벽한 코덱이 도달할 이미지).
400 스텝 Adam, 코사인 감쇠.

| | full | A 후드 | B 전면 | 난간 |
|---|---|---|---|---|
| **M0** 현재 모델 | 20.42 | 21.89 | 19.42 | 없음 |
| **M2** z 16,384개만 최적화, 디코더 동결 | 23.12 | 23.11 | 21.24 | **없음** |
| **M3** z + 디코더 전부 자유 (이 스냅샷에 과적합) | **30.84** | **32.29** | **29.24** | **선명한 직선** |
| M4 가우시안 79,821개 직접 최적화 | 25.12 | 24.91 | 24.80 | (미수렴, 참고용) |

읽는 법:

- **M3 이 난간을 그린다** → 폴딩 템플릿 + 속성 헤드의 *출력 공간* 은 난간을 표현할 수 있다.
  래스터라이저, 템플릿 파라미터화, 6-number 프레임 어느 것도 벽이 아니다.
- **M2 는 못 그린다** → 16,384 latent 를 통과하는 경로에서 막힌다. 다만 M2 는 단일 뷰
  이미지 L1 최적화라 국소최적에 빠질 수 있으므로, "16,384 로는 불가능"의 증명은 아니다.
  아래 §2 의 용량 측정이 더 강한 근거다.
- M4 는 lr 3e-3 / 400 스텝으로 수렴하지 않았다 (마지막 100 스텝에서 24.6→25.1 상승 중).
  **천장으로 인용하면 안 된다.**

이미지: `mdmd/detail_bottleneck_20260917/ladder_A_hood_rail.png`, `..._B_front_rail.png`

## 2. 셀 내부 기하의 고유차원 — shape 3 은 절반을 버린다

모델 무관 측정. 셀마다 점들을 자기 PCA 프레임으로 보내 각 축 단위분산으로 정규화(=
6-number 프레임이 이미 담당하는 몫을 몫으로 나눔) 후 부드러운 3D 점유 히스토그램.
**split-half 잡음 바닥을 직접 재서 보정** (셀 점들을 무작위 절반으로 갈라 두 기술자
사이 거리로 표본 잡음을 추정).

| 코드 차원 | 잡음 보정 후 설명분산 |
|---|---|
| 1 | 23% |
| 2 | 41% |
| **3 (현재 budget_shape)** | **54%** |
| 4 | 68% |
| 6 | 88% |
| 8 | 100% |

빈 수 3→16 스윕에서 bins≥6 부터 값이 안정 (54%/68%/88%/100%). 잡음 비율은 어느
해상도에서나 23~24%.

> **2026-09-17 정정.** 이 자리에 원래 "이전에 잰 모델의 셀 내부 NRMSE 0.950 은 k=3 의
> 상대오차 0.945 와 사실상 같다 → 인코더는 이미 3차원 천장에 붙어 있고 더 얻을 기하
> 이득은 없다" 고 썼다. **틀렸다.** 0.950 은 다른 세션에서 다른 기술자로 잰 값이라 0.945
> 와 맞붙일 수 없는 숫자였다. 같은 기술자로 다시 재니 모델의 도달률은 천장 근처가 아니다
> (§2.1). 인코더/손실 쪽에 큰 여지가 남아 있다.

### 2.1 그래서 모델은 천장의 어디쯤인가 (같은 기술자, 2026-09-17 추가)

GT 셀과 예측 셀 각각을 **자기** PCA 프레임으로 정규화한 뒤 같은 기술자로 비교.
"자기 프레임" 은 6-number frame 이 담당하는 몫(위치·방향·축길이)을 몫으로 나눈 것이므로,
남는 것이 곧 **shape 3 이 얹어야 할 구조** 다. "공통(GT) 프레임" 은 프레임 오차까지 포함한다.

| 체크포인트 | 프레임 1축 각도차 | 자기 프레임 상관 | 공통 프레임 상관 | pred l3/l1 |
|---|---|---|---|---|
| E1 16k (pre-C1) | 49.5° | +0.067 | +0.140 | 0.390 |
| C1 16k (normalize_pooler_xyz) | 47.4° | +0.021 | +0.189 | 0.431 |
| T16k 70k (pre-C1) | 28.7° | +0.057 | +0.498 | 0.295 |
| C1 20k | 34.9° | +0.045 | +0.334 | 0.369 |
| D1 71k (속성 모멘트 1000스텝) | 30.2° | **+0.138** | +0.443 | 0.377 |

(GT l3/l1 = 0.504. 무작위 축이면 각도차 60°.)

읽는 법:

- **공통 프레임 상관 0.50 (T16k)** — 모델은 셀별 타원체(위치·방향·비등방)를 절반쯤 맞춘다.
  앞서 "모델 재현 0%" 로 보였던 것은 프레임 오차가 섞인 탓이다.
- **자기 프레임 상관 0.06** — 그 타원체를 **넘어서는** 내부 구조는 무상관이다.
  즉 §2 의 3d 천장 55% 는 거의 손도 닿지 않은 채 남아 있다.
- **프레임 1축 각도차 28.7°** 는 그 자체로 큰 오차다. 난간 방향이 29° 틀어지면 선이 뭉개진다.
- **pred 셀이 GT 보다 납작하다** (l3/l1 0.295~0.43 vs GT 0.504). 계통 편향.

### 2.2 normalize_pooler_xyz (C1) 는 이걸 얼마나 해결했나

같은 스텝(16k) 비교에서 C1 이 pre-C1 대비 프레임 각도 49.5→47.4°, 공통 프레임 상관
0.140→0.189, 비등방 0.390→0.431 (GT 0.504 쪽으로) 로 **조금씩 낫다**. 자기 프레임 상관은
0.067→0.021 로 오히려 낮다.

그러나 **깨끗한 절제가 아니다.** E1 과 C1 은 `decoder_refine_start`(8000 vs 400),
`folding_res_start`(8000 vs 0), `detail_start`(20000 vs 40000), `max_steps`(16000 vs 64000,
따라서 step 16000 에서의 lr 이 전혀 다름) 까지 함께 다르다. 전용 절제 런 없이는 귀속 불가.

결론: C1 의 방향(죽어 있던 shape 채널을 살림, 절제 반응 0.209%→10.90%)은 옳지만,
그것이 **올바른 셀 내부 패턴** 으로 이어지지는 아직 않았다. 자기 프레임 상관은 두 쪽 다
0.02~0.07 이다. 채널이 출력에 영향을 준다는 것과 맞는 값을 싣는다는 것은 다르다.

난간 셀이 특별히 나쁜 것도 아니다 (k=3 상대오차: 난간셀 0.941 vs 나머지 0.946).
**난간만의 문제가 아니라 모든 셀의 내부가 통째로 날아간다.** 난간은 그게 눈에 보이는
곳일 뿐이다.

## 3. 셀 내부 기하의 59.9% 는 씬에 고정이다 ← 가장 큰 구조적 기회

같은 기술자로 train 씬의 스냅샷 10개(3DGS step 12,000 ~ 30,000)를 비교.

| | 원자료 | 잡음 보정 후 |
|---|---|---|
| 셀 간 변동 (스냅샷 불변 = 씬 고정) | 51.8% | **59.9%** |
| 스냅샷 간 변동 (시간에 따라 변함) | 48.2% | 40.1% |

(스냅샷 간 변동의 30.4% 는 표본 잡음이었다.)

씬-고정 성분을 준 뒤 남는 **동적** 성분의 고유차원: 3d 53%, 4d 65%, 6d 85%, 8d 98%.

따라서 셀 내부 기하를 "씬 고정분 + 스냅샷 동적분" 으로 나누면

    59.9%  (고정, 부가정보로 무료)
  + 40.1% × 53%  (동적, shape 3 이 담는 몫)
  = 81%

현재의 54% 대비 **설명 못 하는 잔차가 46% → 19%, 2.4배 감소**.

난간은 스냅샷마다 움직이지 않는다. 지금은 그 정적 구조를 매 스냅샷 16,384 숫자로
다시 보내려 하고 있고, 그럴 여유가 없다.

## 4. 셀 내부 속성 — 용량은 있는데 안 쓴다

### 4.1 고유차원 (셀내 std 11 + 셀 로컬 위치→속성 최소제곱 기울기 33 = 44차원 기술자)

|---|---|
| 3 | 39% |
| 6 | 61% |
| **8 (현재 budget_appearance)** | **73%** |
| 11 | 86% |
| 16 | 100% |

### 4.2 실제로 쓰고 있는 양

셀 내부 표준편차, 표준화 채널:

| 채널 | GT | pred | 비율 |
|---|---|---|---|
| xyz | 0.0051 | 0.0050 | **0.98** |
| **logscale** | 1.5481 | 0.6031 | **0.39** |
| opacity | 4.4448 | 2.2199 | 0.50 |
| rot | 0.2027 | 0.1070 | 0.53 |
| sh_dc | 1.0066 | 0.6603 | 0.66 |

셀 내부에서 위치가 속성을 설명하는 정도 (선형 R²):

| 채널 | GT | pred |
|---|---|---|
| logscale | 0.234 | **0.045** |
| sh_dc | 0.226 | 0.050 |
| opacity | 0.125 | 0.049 |
| rot | 0.132 | 0.037 |

**점은 정상적으로 퍼지는데(0.98) 속성만 셀 평균으로 뭉친다.** 난간·모서리는 "이웃과
크기가 다른 길쭉한 가우시안 몇 개" 이므로 이 붕괴가 곧 디테일 소실이다. 그리고
`attr_read_shape=1` 이라 속성 헤드는 슬롯 위치를 읽고 있는데도 공간 변조를 거의 하지
않는다 (0.045 vs 0.234).

기하와 달리 **여기는 천장이 아니라 미사용이다**: 8차원이 73% 를 담을 수 있는데 실제
전달량은 40% 수준.

### 4.3 detail 단계는 이걸 고치지 못했다

T16k 는 `detail_start 44000`, `edge_gain 4.0`, `w_render_perc 0.05` 로 26,000 스텝을
돌고 70,000 에서 끝났다. 그런데도 분산비는 0.39 다. 렌더 손실은 **합성된 이미지** 만
보므로 셀 내부에서 속성이 평균으로 뭉쳤는지 아닌지를 볼 수 없다. 엣지 가중치는
"어느 픽셀을 더 볼까" 를 바꿀 뿐 "한 셀 안에서 가우시안들이 서로 달라야 한다" 는
말을 하지 않는다.

## 5. 셀 분할 자체는 문제가 아니다

- 1024 셀 × 256 슬롯, 실제 점 79,821개 (평균 78/셀, p10 24 / 중앙값 71 / p90 145), 빈 셀 31개
- 난간 영역 B 의 점을 담은 셀 142개 중, 셀 점의 **94.6%(중앙값)** 가 그 영역 안에 있다
  → k-means 앵커는 공간적으로 잘 뭉쳐 있고, 난간이 벽과 한 셀에 섞여 희석되는 구조가 아니다
- 셀 PCA 축비 중앙값 1.00 : 0.56 : 0.22. `folding_aniso_log_cap 1.5` (축비 최대 e³ ≈ 20)
  이면 6-number 프레임이 관측된 셀 모양을 덮는다
- 선 모양 셀(l2/l1 < 0.10) 은 1.5% 뿐

즉 "앵커를 더 쪼개라" 는 방향은 측정이 지지하지 않는다. 문제는 셀 **안쪽** 이다.

## 6. 무엇을 추가·축소·유지할 것인가

### 추가 ①② (구현 완료, D1 런에서 검증 중)

`losses.py :: intra_group_attr_moment_loss` — 셀 내부 속성 2차 모멘트 직접 정합.

- `--w_attr_spread` : 셀별·채널별 `|std_pred − std_gt|` (표준화 채널)
- `--w_attr_slope`  : 셀 로컬 좌표 → 속성의 11×3 최소제곱 기울기 차이

둘 다 집합 함수라 슬롯 순서에 무관하고, `intra_group_attr_set_loss` docstring 이 지적한
"같은 자리의 서로 다른 GT 두 개를 평균내는" 문제를 겪지 않는다. `attr_set` 이 속성공간
chamfer 로 붕괴를 간접적으로 벌한다면, 이쪽은 붕괴의 **정의** 를 직접 맞춘다.

레이트 0, 구조 변경 0, 예산 4|1|3|8 그대로.

실측 항 크기 (T16k 70k): `attr_spread 0.464`, `attr_slope 0.483`, `attr_set 1.493`
(학습 로그의 `aset 1.63` 과 일치 → 표준화·레이아웃 정합 확인).
`w_attr_set=3.0` 이 목적함수의 11% 이므로 `w=5.0` 이면 각각 약 5%.

단위 테스트: 자기 자신 → 0 / 셀 평균 붕괴 → 2.07 / 슬롯 셔플 → 0 (순열 불변) /
분산비 0.39 에서 SGD 30스텝에 0.390 → 0.405 (방향 정상).
bf16 autocast 아래서 `linalg.solve` 가 없어 항 전체를 fp32 로 고정함.

### 추가 ③ (제안, 미구현) — per-scene 앵커 피처

§3 의 59.9% 를 회수하는 유일한 방법. Scaffold-GS 의 앵커 피처, 비디오 코덱의 I-프레임,
VQ-VAE 코드북과 같은 **부가정보** 범주. `PLAN_10B_ANCHOR_KR.md` 의 §10.B 를 인코더 전용에서
디코더까지 확장하는 것.

- 씬마다 `nn.Embedding(1024, F)` 를 두고, 디코더가 셀 토큰 16채널 옆에 붙여서 읽는다
- F=32 면 씬당 32,768 float. 스냅샷 3,000개에 분산하면 **스냅샷당 11개 숫자 = latent 16,384 의 0.07%**
- 예산 4|1|3|8 은 손대지 않는다. 메인 novelty(262,144 → 16,384) 그대로
- 0 으로 초기화하면 시작 시점에 no-op 이므로 T16k 체크포인트에서 파인튜닝으로 검증 가능
- 새 씬 일반화 프로토콜도 깔끔하다: 나머지를 얼리고 그 씬의 앵커 테이블만 적합

### 축소 ④⑤

- `w_proj_hist` 2.5 → 0.5. 목적함수의 **20~21%** (C1 로그에서 단일 최대 항) 인데,
  축정렬 2D 주변 밀도만 맞추는 항이라 디테일을 만들 수 없다. xyz 셀내 분산비는 이미
  0.98 이고 전역 위치는 해결된 상태다. 단 L16k(`w=0`)가 전체적으로 더 나빴으므로
  0 으로 내리지 말고 축소만 하고, 반드시 A/B 로 확인할 것.
- `w_plane_chamfer` 2.5 → 1.0. 같은 이유(축정렬 2D 실루엣).

### 삭제

없음. 측정상 명백히 해로운 항은 나오지 않았다.

### 유지

`w_attr_set 3.0`, `w_intra_sinkhorn 4.0`, `w_coverage 1200`, detail 단계 설정 모두 유지.
detail 단계가 속성 붕괴를 못 고친 것은 사실이지만(§4.3), 이전 측정에서 held-out 뷰 8개
전부 +0.27 ~ +1.53 dB 개선했으므로 해로운 것은 아니다.

## 7. 실행 중인 검증

`runs/D1_moment_*` — T16k step 70,000 에서 재개, GPU 3 단독.
`--w_attr_spread 5.0 --w_attr_slope 5.0`, 그 외 T16k 와 완전 동일.
`--max_steps 140000 --lr 2.4e-4` 로 step 70,000 에서의 유효 lr ≈ 1.2e-4 확보
(원래 스케줄이면 7.9e-6 라 아무것도 안 움직인다). `max_steps` 는 코사인 lr 과 루프
종료 조건 외에는 아무 스케줄에도 쓰이지 않음을 확인함.

1차 판정 지표는 **셀 내부 속성 분산비** (0.39 → ?). 이 수치는 목적함수의 다른 어떤 항도
움직일 이유가 없으므로 기여도 귀속이 깨끗하다. 2차 지표는 난간 크롭 PSNR 과 육안.

이어서 필요한 대조군: 같은 lr 로 `w_attr_spread = w_attr_slope = 0` 인 런.
